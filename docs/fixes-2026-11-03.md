# Correcciones de uso con mando — 3 de noviembre de 2026

Este informe corresponde a 2.5.1. La corrección posterior de las imágenes, YouTube y el nuevo servicio
opcional para Input se documentan en [la revisión 2.5.2](fixes-2.5.2.md).

## Resultado

La compilación local 2.5.1 corrige el selector Input dentro de Luma, agrupa las entradas idénticas del
sintonizador, sustituye la letra dibujada de Netflix por el banner que aporta la app (icono como alternativa) y añade movimiento continuo
de aplicaciones. Settings → Up Next permite consultar el origen de los datos y reiniciar su presentación.

Now Playing comprueba si existe la pantalla de permisos antes de abrirla. En esta Xiaomi no existe y muestra
una explicación con el comando ADB. El permiso continúa pendiente: la revisión automática rechazó concederlo
sin autorización expresa porque Android permite al listener acceder a notificaciones potencialmente sensibles.
No se ha concedido ese acceso durante esta intervención.

## Evidencia en la Xiaomi MiTV-MSSP3

- Antes del cambio, enviar `KEYCODE_TV_INPUT` con Luma delante no abría un selector visible.
- El servicio `com.mediatek.tvinput/.tuner.TunerInputService` publica `HW0` y `HW5`, ambos con la etiqueta
  «Sintonizador». Se agrupan por proveedor, servicio y etiqueta; los puertos AV/HDMI conservan sus nombres.
  Los identificadores por sí solos no demuestran cuál corresponde al modo analógico o digital.
- La acción `android.settings.ACTION_NOTIFICATION_LISTENER_SETTINGS` devuelve `No activity found`.
- La «N» anterior se pintaba mediante `Canvas.drawText("N", ...)` y una fuente genérica.
- El menú anterior solo ofrecía movimientos de una posición y no tenía un modo continuo.
- Up Next consulta `content://android.media.tv/watch_next_program`. En la pantalla original había contenidos
  publicados por HBO Max y Atresplayer. Completa los huecos con estadísticas de uso, si hay permiso, o el
  registro local de las apps abiertas desde Luma.

El reinicio guarda una fecha local: oculta programas y usos anteriores, borra el registro local de recientes y
deja que vuelva a aparecer actividad posterior. No modifica el proveedor de Android ni el historial de las cuentas.

## Input nativo: causa confirmada y pendiente

La captura de las tres pulsaciones físicas muestra `KEYCODE_TV_INPUT` (178). El receptor
`com.xiaomi.android.tvsetup.partnercustomizer.GlobalKeyReceiver` las recibe mediante
`ACTION_GLOBAL_BUTTON` e intenta abrir explícitamente
`com.google.android.tvlauncher/.inputs.InputsPanelActivity`, con acción
`com.android.tv.action.VIEW_INPUTS`. El registro termina con `ActivityNotFound` porque el paquete
Android TV Home está desactivado.

El selector alternativo de PatchWall (`com.mitv.tvhome.atv/.app.tv.InputSourcePopupActivity`) sí se puede
abrir explícitamente al habilitar su paquete, pero el mando no lo utiliza. Habilitar solo PatchWall no
arregló Input: el usuario lo comprobó y confirmó que no hacía nada.

Se probó habilitar Android TV Home y fijar otra vez Luma como inicio. Aunque el comando devolvió `Success`,
la resolución de Home volvió a `com.google.android.tvlauncher/.MainActivity`, con prioridad 2. El firmware
también rechaza cambiar estados individuales de componentes desde ADB con `SecurityException`.
Se revirtieron los ensayos: Android TV Home y PatchWall quedan desactivados para el usuario (estado 3), y
el inicio vuelve a `dev.luma.tv/.MainActivity`.

**El botón físico sigue pendiente.** El manejador nuevo funciona cuando el evento llega a la actividad,
pero este firmware lo intercepta antes. Recuperar Input conservando Luma requiere otro mecanismo de remapeo;
no se ha instalado ni habilitado un servicio de accesibilidad.

## Verificación

Se instaló primero una copia QA del código anterior: las cinco comprobaciones iniciales fallaron. La versión
corregida pasó ocho comprobaciones sobre las vistas, entradas y proveedor reales de la TV:

1. El manejador Input abre opciones visibles cuando el evento llega a la actividad (despacho directo).
2. El sintonizador no repite etiqueta.
3. La pantalla de permisos ausente ofrece una alternativa concreta.
4. Move continúa entre direcciones, guarda con OK y conserva el orden al reconstruir la pantalla.
5. Back cancela sin cambiar el orden guardado.
6. Los intents de HDMI y TV tienen un manejador instalado; el sintonizador no usa una URI de passthrough.
7. Mover desde Home permite pasar de los seis favoritos y vuelve a Home al guardar.
8. Reiniciar Up Next oculta lo anterior y acepta actividad posterior.

```sh
LUMA_DEVICE=IP_DE_LA_TV:5555 \
ANDROID_SDK_ROOT="$PWD/.local/toolchain/sdk" \
LUMA_JDK="$PWD/.local/toolchain/jdk/Contents/Home" \
bash tools/test-tv.sh
```

También pasaron los 26 casos existentes de reconocimiento de dispositivos, las siete pruebas de recuperación,
la comprobación de sintaxis de shell y `git diff --check`.

La prueba de intents comprueba que Android puede resolverlos; no acredita una reproducción correcta de señal
HDMI o de canales. Tampoco se ha probado reproducción musical con el permiso de notificaciones concedido.

## Instalación y límites

La versión oficial usa la firma del autor y no admite una actualización firmada con la clave local. Al principio
se instaló una copia paralela `dev.luma.tv.local`. El usuario rechazó esa organización y autorizó sustituir la
oficial por nuestro fork con el identificador habitual `dev.luma.tv`, retirando la copia paralela. El procedimiento,
la clave privada excluida de Git y las instrucciones de actualización se documentan en
[Nuestra versión de Luma](OWN_FORK.md). No se ha reiniciado Up Next.
